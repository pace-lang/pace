While running a single file is great for small scripts, real applications require multiple files and dependencies. The Pace toolchain provides a built-in package manager and build system to make this effortless.

## Creating a Project

To create a new Pace project, use the `pace new` or `pace init` command.

> [!IMPORTANT]
> Pace project names are strictly enforced to use `kebab-case` (e.g., `my-app`). They must start with a lowercase letter and contain only lowercase letters, numbers, and hyphens (`[a-z0-9-]`).

```bash title="Terminal"
# Create a new project in a specific directory
pace new my-app

# Initialize a new project in the current directory
pace init
```

This will generate the standard directory structure required by the compiler:

### Structure Breakdown

- **`src/`**: This is where all of your Pace source code (`.pace` files) lives. 
  - **`src/main.pace`**: The entry point for executable projects.
- **`pace.toml`**: The configuration file that defines project metadata and dependencies.
- **`target/`**: This directory is automatically generated by the compiler. It contains the compiled native executables and intermediate build artifacts.
- **`.gitignore`**: Pre-configured to ignore the `target/` directory.

## Configuration (`pace.toml`)

Every Pace project is governed by a `pace.toml` file located in the root of the project.

```toml title="pace.toml"
[package]
name = "my-project"
version = "0.1.0"
authors = ["Your Name <you@example.com>"]

[dependencies]
http = "1.0.0"
json = "0.5.2"
```

- **`[package]`**: Contains core metadata. The `name` field dictates the name of the executable generated by the compiler.
- **`[dependencies]`**: Lists all external packages your project relies on. When you build the project, the Pace toolchain will automatically fetch and link these dependencies.

## Building and Running

The Pace CLI provides commands to compile your code into native machine code.

### `pace run`
Compiles and immediately runs the current Pace project. This is the recommended command for local development and testing.

```bash title="Terminal"
pace run
```

### `pace build`
Compiles the project into a native executable and places it in the `target/release/` or `target/debug/` directory.

```bash title="Terminal"
pace build
```

### `pace lint`
Runs the built-in style linter across your project without fully compiling it. It checks for Pace naming conventions (e.g., `camelCase` for functions/variables, `PascalCase` for types) and exits with a status code of `1` if any style violations are found. Perfect for CI/CD pipelines!

```bash title="Terminal"
pace lint
```

### Useful Flags
- `--release`: Build the project with aggressive compiler optimizations enabled. This will take longer to compile but produce a significantly faster executable (e.g., stripping debug symbols and enabling `speed_and_size` opts).
- `--verbose`: Enable detailed logging during compilation.

```bash title="Terminal"
pace build --release
```

## Toolchain Management

### `pace upgrade`
Automatically fetch and install the latest version of the Pace language SDK directly from the terminal. This command updates your global CLI and runtime library across UNIX and Windows environments.

```bash title="Terminal"
pace upgrade
```
