We are incredibly excited to announce **Pace v0.2.0**! 🎉

> [!NOTE]
> **What is a Release Candidate (RC)?**
> Because we have shipped a massive number of architectural changes in just a few days, this release is marked as an RC. This means the features are fully implemented, but we are letting them "bake" in the real world to find any edge cases, memory leaks, or ergonomic flaws before officially tagging the final `v0.2.0` release. We encourage you to test it and report bugs!

With our v0.1.0 release, we introduced Pace to the world as a fast, safe, and intuitive language. In v0.2.0, we focused intensely on turning Pace into a **"Useful Application Language"**. We've dramatically expanded the type system, added highly requested syntactical sugar, and completely re-architected the standard library.

Here is a deep dive into the biggest features and improvements in Pace v0.2.0.

---

## 🚀 Major Features

### Generics & Algebraic Data Types
Pace now features a robust generics system, powering full monomorphization for functions, classes, and enums. This allows developers to write highly reusable, type-safe code without sacrificing native runtime performance. 

Building on generics, we have officially introduced **Standard Generic Algebraic Data Types**, including `Option<T>`, `Result<T, E>`, `List<T>`, and `Map<K, V>`.

### Pattern Matching (`match`)
To compliment the new Algebraic Data Types, Pace now supports comprehensive pattern matching via the `match` expression! You can now safely unwrap variants and extract payloads with compile-time exhaustiveness checking.

```pace
let result = fetch_data();
match result {
    Ok(data) => print("Success: \{data}"),
    Err(e) => print("Failed with error: \{e}")
}
```

### List Comprehensions
Transforming data just got a lot cleaner. You can now map iterables in a single, elegant line of code using list comprehensions (`[expr for item in iterator]`). 

Under the hood, the Pace compiler natively lowers these comprehensions into highly-optimized, pre-allocated array loops. You get beautiful Python-like syntax with zero hidden runtime reallocation overhead!

```pace
let arr = [1, 2, 3, 4];
let doubled = [x * 2 for x in arr]; // [2, 4, 6, 8]
```

### Null-Safety Operators
Dealing with optional data is now frictionless. We've introduced full support for the null-coalescing operator (`??`) and the null-coalesce assignment operator (`??=`). This allows you to easily provide default fallbacks for `T?` types.

### String Interpolation
Pace now supports string interpolation using both `\{expr}` and `${expr}` syntax. Expressions are directly evaluated and safely concatenated inside string literals—no manual type conversions necessary!

```pace
let name = "Pace Developer";
print("Welcome to v0.2.0, \{name}!");
```

## 🏗️ Architecture & Tooling

### Built-in Style Linter & CLI Checks
Pace v0.2.0 introduces a brand new, highly opinionated style linter built directly into the compiler pipeline. It intelligently enforces the Pace design philosophy (`camelCase` for functions and variables, `PascalCase` for types and constants) without failing compilation for perfectly valid code. You can run the dedicated `pace lint` command to strictly enforce these checks (great for CI/CD pipelines!), and warnings will naturally print alongside type errors during a standard `pace build`.

### Strict Project Naming
We've locked down package naming conventions to enforce ecosystem consistency. `pace new` and `pace init` now strictly require project names to use `kebab-case`, start with a lowercase letter, and contain only `[a-z0-9-]`. This ensures seamless integration with future package registries and cross-platform paths.

### Dynamic Standard Library
We have successfully decoupled standard types from the core compiler. The compiler now recursively crawls and globally injects the `stdlib/src/` folder during compilation. Types like `Map`, `File`, and `print` are now completely standard library components powered by `foreign func` definitions. 

### Local Module Resolution
We've overhauled the module loader! Imports like `import "math_utils"` now successfully resolve if `math_utils.pace` exists in your local directory. No more fighting with explicit relative paths or package configurations for simple sibling modules.

### Function Overloading
The compiler now supports function overloading via a custom name mangling system. Developers can declare multiple functions with the same name, so long as their parameter signatures differ!

### Upgraded Diagnostics
CLI-level project errors (e.g., missing `main` function, linker issues, missing `pace.toml`) are now beautifully styled global diagnostics (like `[E001]`). If a required system C compiler is missing, the linker now detects your OS and prints the exact terminal commands needed to install it. We've also added these robust compiler checks directly into the installation scripts, so you're alerted during setup rather than halfway through building your first project!

### Optimized Release Builds
The `pace build` and `pace run` commands now officially support the `--release` flag! Running in release mode automatically leverages Cranelift optimizations (`speed_and_size`) and strips debug symbols during the linking phase, radically shrinking the size of your compiled binaries and producing a lightning-fast executable.

### Seamless CLI Upgrades
You can now update your Pace installation directly from the terminal by simply running `pace upgrade`. It handles fetching and executing the latest toolchain installer natively for both UNIX and Windows environments.

### Ergonomic Project Creation
The `pace new <name>` command has been revamped. In addition to a cleaner Cargo-like console output, it now provides helpful step-by-step instructions (e.g., `cd my-app` and `pace run`) so you can jump into coding immediately.

## 🔒 Safety Enhancements

- **Constructor Initialization Checks**: The typechecker now rigorously tracks uninitialized properties inside class constructors, producing robust compile-time errors if you attempt to use a partially initialized object.
- **Access Modifiers**: We've introduced explicit `public` and `private` keywords, dropping the legacy underscore (`_`) convention for visibility control. 
- **ARC Memory Leaks Fixed**: We've resolved lingering memory leaks in the Automatic Reference Counting (ARC) implementation, making long-running Pace applications significantly more stable.
